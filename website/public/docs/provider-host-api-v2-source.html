Provider 5 consumer reference ​

Provider 5.0.0 is a fresh-install Provider for Host API forms.takoform.com/v2. It maps thirteen exact published Edge Form URLs from the takoform-forms publisher to Terraform/OpenTofu resources and never negotiates or falls back to v1. Check the live Registry listing and exact version readback before installing or pinning 5.0.0; this reference does not state current Registry availability. Provider 4.1.0 remains the published v1 client. A compatible Host must independently advertise support for each exact Form before use.

The Host API identity and discovery path are defined in the Provider's v2 protocol identifiers and HTTP client. These links describe the client implementation; they are not a claim that a particular Host implements or supports the API.

The mounted Terraform/OpenTofu resource type names are takoform_module_worker, takoform_worker_bundle, takoform_worker_version, takoform_worker_deployment, takoform_worker_endpoint, takoform_worker_cron_trigger, takoform_edge_kv_namespace, takoform_edge_object_bucket, takoform_sqlite_database, takoform_sqlite_migration_set, takoform_sqlite_migration_application, takoform_at_least_once_queue, and takoform_queue_consumer. Their HCL spec object is typed per exact Form; the four empty-spec Forms omit that attribute. Artifact Forms carry typed artifact.url and artifact.sha256 inputs. This Provider forwards those identities; it neither publishes artifact bytes nor grants the Host permission to fetch arbitrary sources. WorkerVersion's arbitrary public vars value is authored as spec.vars_json, validated as strict JSON by the exact Form codec.

Example: Worker identity and deployment relationships ​

Resource references use exact Host-assigned UIDs, not name lookup. These references let Terraform order the resources and pass those UIDs to the Provider:

hcl
resource "takoform_module_worker" "api" {
  name = "api"
}

resource "takoform_worker_bundle" "api" {
  name = "api-bundle"
  spec = {
    artifact = {
      url    = var.bundle_url
      sha256 = var.bundle_sha256
    }
  }
}

resource "takoform_worker_version" "api" {
  name = "api-v1"
  spec = {
    worker   = { resource_uid = takoform_module_worker.api.uid }
    bundle   = { resource_uid = takoform_worker_bundle.api.uid }
    handlers = ["fetch"]
  }
}

resource "takoform_worker_deployment" "api" {
  name = "api-live"
  spec = {
    worker = { resource_uid = takoform_module_worker.api.uid }
    versions = [{
      worker_version = { resource_uid = takoform_worker_version.api.uid }
      weight         = 10000
    }]
  }
}

resource "takoform_worker_endpoint" "api" {
  name = "api-endpoint"
  spec = {
    worker = { resource_uid = takoform_module_worker.api.uid }
  }
}

bundle_url and bundle_sha256 must identify the same artifact; the example does not publish or upload it. The Host assigns and returns the worker UID. The deployment references the worker and version, while the endpoint references the worker; the Host controls resulting endpoint and runtime behavior.

For a queue relationship, takoform_queue_consumer.spec.queue and .worker also take exact UIDs:

hcl
resource "takoform_at_least_once_queue" "events" {
  name = "events"
  spec = { message_retention_seconds = 86400 }
}

resource "takoform_queue_consumer" "events" {
  name = "events-consumer"
  spec = {
    queue                     = { resource_uid = takoform_at_least_once_queue.events.uid }
    worker                    = { resource_uid = takoform_module_worker.api.uid }
    max_batch_size            = 10
    max_batch_timeout_seconds = 5
    max_concurrency           = 1
    max_retries               = 3
    retry_delay_seconds       = 10
  }
}

Build and load a local plugin ​

Use a fresh evaluation module, separate from existing v4 state. From this repository root, build the default v2 plugin into an absolute directory:

console
PROVIDER_DEV_DIR="$(mktemp -d)"
go build -ldflags="-X main.version=5.0.0-dev" \
  -o "$PROVIDER_DEV_DIR/terraform-provider-takoform" .

Create a CLI configuration file at $PROVIDER_DEV_DIR/dev.tfrc, replacing /absolute/provider-dev-dir with that directory's actual path:

hcl
provider_installation {
  dev_overrides {
    "registry.terraform.io/tako0614/takoform" = "/absolute/provider-dev-dir"
  }
  direct {}
}

In the fresh module, declare the canonical Provider source in required_providers, add the v5 configuration below, and declare any referenced root variables. Run CLI commands with this override explicitly selected:

console
TF_CLI_CONFIG_FILE="$PROVIDER_DEV_DIR/dev.tfrc" tofu providers schema -json
TF_CLI_CONFIG_FILE="$PROVIDER_DEV_DIR/dev.tfrc" tofu validate

Use terraform in place of tofu for Terraform. These commands load the local plugin; schema inspection does not contact a Host. The CLI's development override warning is expected. In a minimal module using only this Provider and local state, skip init for this evaluation: it still tries to select a published Registry version. If other Providers, modules, or a remote backend need initialization, initialize them separately according to their own requirements. See the OpenTofu CLI configuration and Terraform development override documentation.

After initializing custody and supplying a compatible Host, use the same CLI configuration to review tofu plan. Applying changes the selected Host. Keep the override scoped to this evaluation; omit TF_CLI_CONFIG_FILE when returning to ordinary Registry installation. A development build is not a signed release, a Registry package, or Host support evidence.

Intent-store custody before resource planning ​

Select exactly one intent-store mode. In local mode, a caller must initialize one private, absolute-path store for one fixed management scope and exact Host API root. The store is an execution-owner durability obligation; do not put it in an ephemeral directory that disappears between plans, applies, refreshes, or process restarts.

sh
"$PROVIDER_DEV_DIR/terraform-provider-takoform" intent-store-init \
  --path "$INTENT_STORE_PATH" \
  --store-id "$CALLER_SCOPE_ID" \
  --host-api "https://host.example/apis/forms.takoform.com/v2"

A locally built Provider binary exposes this subcommand, so initializing a store does not require the Go source tree. From a source checkout, go run ./cmd/intent-store-init accepts the same flags. Neither invocation installs the Provider through the Terraform Registry.

The tool refuses mismatched or nonempty unbound stores. store-id is a fixed local label, not authentication or proof that a rotated bearer token has the same Host principal. The execution owner must retain the store and the actual Host principal/authorization continuity. Loss, corruption, a changed path/root/ID, or an unresolved claim stops mutation; it does not silently create a replacement store.

hcl
provider "takoform" {
  endpoint      = "https://host.example"
  host_api_root = "https://host.example/apis/forms.takoform.com/v2"
  token         = var.host_token
  store_path    = var.absolute_private_store_path
  store_id      = var.fixed_caller_scope_id
  space         = "prod"
}

resource "takoform_worker_endpoint" "api" {
  name = "api"
  spec = {
    worker = { resource_uid = var.existing_worker_uid }
  }
}

For remote mode, set intent_store_slot instead of store_path. This is an opaque slot name, not a path or credential. It is usable only when the Runner/OpenTofu execution environment explicitly grants the Provider generic private-file access for that exact slot. The Provider does not provision this capability, and no runtime default Cloud mount or ambient authentication is implied. The snapshot backend note documents the Runner descriptor inputs, conditional snapshot commits, and receipt handling. For example, with runner_private_slot supplied by that explicitly capable environment:

hcl
provider "takoform" {
  endpoint          = "https://host.example"
  host_api_root     = "https://host.example/apis/forms.takoform.com/v2"
  token             = var.host_token
  intent_store_slot = var.runner_private_slot
  store_id          = var.fixed_caller_scope_id
  space             = "prod"
}

Exactly one of store_path and intent_store_slot must be configured. During Configure, before resource planning, remote mode reads the selected private slot and conditionally initializes an absent slot with an empty snapshot bound to the same store_id and exact host_api_root; this is private-store traffic, not a Host API request. A concurrent initializer is accepted only if the winning snapshot has that exact binding. Malformed, mismatched, or unresolved storage state is refused before Host mutation. Local mode instead opens the already initialized path and makes no HTTP request. Both modes use the same intent-store rules described in the journal implementation note.

Before any Host mutation, the journal must have an exact acknowledged durable snapshot commit. If a commit acknowledgement is lost or unknown, the Provider checks only that exact commit; it proceeds only on an exact receipt and refuses to mutate while the outcome remains unresolved. This storage acknowledgement is separate from acknowledgement of the Host mutation itself.

Each resource validates state and custody before v2 discovery. Discovery's baseUrl must equal host_api_root exactly. The Host's authorized exact Form support and Offering policy are checked for a new Create. If Offerings are advertised, set both offering_id and offering_revision; otherwise omit both. There is no default Offering.

Recovery and private inputs ​

Each Create/Update/Delete durably records the original public request, idempotency key, first-send time, and advertised replay window before its first Host mutation. The store excludes bearer credentials and private-input values. Once an Operation is acknowledged, the Provider follows that exact Operation and reads the exact Resource UID before settling state. An accepted ACK whose Terraform state was lost can be reconstructed by those two reads without a second mutation. A pre-ACK claim with no Operation ID is deliberately halted: neither a new key nor automatic replay or name-based adoption is authorized. A failed accepted Resource keeps its UID and name reservation; recovery is an explicit same-UID Update or Delete. Delete releases state only after terminal success and exact UID 404 evidence.

The v2 state schema is version 2. v0/v1 state upgrade is an explicit refusal before HTTP. A fresh UID import uses the configured Space and requires an authorized exact-UID Resource GET with matching Host root, Form, Space, UID, name, and generation before the store binds it. Import does not synthesize a Create, Operation, or prior private input. Do not use import as an automatic orphan-adoption or legacy-state migration path.

For WorkerVersion required_sensitive_vars, the caller supplies the exact Space/name/input-name map only in the Provider process at apply or same-Operation continuation time through TAKOFORM_V2_PRIVATE_INPUTS_JSON. The source shape and constraints are in the private-input source note. Values do not enter spec, HCL resource attributes, Terraform state, the intent store, or diagnostics. A fresh Create requires the full map. An explicit Update may omit privateInputs to retain the Host's prior values; a selected map must still match the declaration exactly. A Host waiting_input Operation requires the entire original map on that same Operation, never a replacement Create/Update.

This source and its local fixture tests do not establish a normal Takosumi Runner's store initialization, persistent filesystem custody, private-input delivery, live Host conformance, artifact availability, Provider release, or GA readiness. Those require their separate owning integrations and evidence.
