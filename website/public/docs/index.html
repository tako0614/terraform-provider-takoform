Evaluate the current v2 source

Provider v2.0.0 is not published in the Registry. The pin below identifies the source candidate; ordinary init cannot install it.

The repository gate builds the provider with the Go toolchain pinned by the release descriptor, then exercises all nine resources through isolated Terraform and OpenTofu development overrides.

Against a real host, first verify that the host advertises the exact v1alpha2 FormRef.

Maintain published Legacy

Pin published provider v1.0.3 for existing v1 state, refresh, delete, and recovery. It does not turn that state into v2 semantics.

Migrate without editing state

  1. Pin provider v1 and refresh the Legacy resource.
  2. Capture non-secret desired configuration and required public outputs.
  3. Create under the exact v1alpha2 FormRef, or import only with host conformance proof.
  4. Move consumers, observe the result, then delete Legacy through v1 after rollback is no longer needed.

Host / Cloud boundary

Takoform owns only workload semantics, schemas, exact identities, packages, and conformance. Host profiles own capability support; adapters own external compatibility; operators own placement, routing, scaling, credentials, and recovery. Takosumi Cloud owns managed capacity, billing, quota, and SLA.

Read the portable-field admission rule

Takoform is an Experimental specification project. Current FormRefs use forms.takoform.com/v1alpha2 and current package envelopes use packages.forms.takoform.com/v1alpha3. Provider v2.0.0 is an unpublished source candidate. Published provider v1.0.3 and the 34 published Form Package identities from forms.takoform.com/v1alpha1 are immutable Legacy evidence. There is no current central approval or admission.

現行v2 sourceを評価する

provider v2.0.0はRegistryに公開されていません。次のpinはsource identityの検証用であり、通常のinitではinstallできません。

repoの完全gateは、release descriptorに固定されたGo toolchainでproviderをbuildし、TerraformとOpenTofuの隔離されたdev overrideを使って9リソースのlifecycleを検証します。

実hostで試す場合は、hostがexact v1alpha2 FormRefをadvertiseしていることを先に確認してください。

公開済みLegacyを保守する

既存のv1 state、refresh、delete、recoveryには公開済みprovider v1.0.3を固定します。新しいv2 semanticsへ自動変換しません。

stateを編集せずに移行する

  1. provider v1を固定し、Legacy resourceをrefreshする。
  2. secretを除くdesired configurationと必要なpublic outputを記録する。
  3. exact v1alpha2 FormRefへ新規createするか、host conformanceが証明されたresourceだけimportする。
  4. consumerを切り替えてobserveし、rollback不要後にv1でLegacyをdeleteする。
