What is published and what is a release candidate ​

This project ships in two tiers. Every page says which tier it is describing, and nothing here mixes them.

No credentials, no placement, no pricing — the host decides those and keeps them out of your state. v1.0.3 remains the published Legacy client for existing v1 state. Start here to install and use it.

Shape-preserving Forms ​

Takoform does not reduce cloud services to a least common denominator. Each Form fixes the complete application-visible shape of one proven service primitive — execution ABI, consistency, delivery guarantees, update units — and leaves only the vendor's identity, account, placement, and commerce to the host. Implementations with different semantics are different Forms; what is exchangeable is the host, never the meaning (decision 0008).

Beta: the Experimental Edge Platform Family ​

Provider release candidate

Everything in this section rides the stable provider v2.1.1 release target. Its descriptor remains candidate-only until owner publication. The 15 exact Forms are Experimental; Beta is their API/family channel, not Stable maturity, and their package artifacts remain unpublished. Runnable configuration lives on the Beta quick start, not on this page, because a fragment of it cannot be applied.

Current design work happens in the namespaced edge.forms.takoform.com/v1beta1 family (Form Families), served over the forms.takoform.com/v1beta1 Host API with UID/generation/revision identity, long-running operations, and content-addressed artifact upload.

Workers use capability through typed bindings (kv_bindings, bucket_bindings, sqlite_bindings, queue_producer_bindings, service_bindings) backed by exact Interface contracts and Binding contracts; inward activation (routes, domains, cron, consumption) is always a separate attachment resource. These typed resources are the whole lane: there is no generic carrier for a Form the provider was not built against, because the lane gives a client no way to verify a FormRef it did not compile in (decision 0021).

How it works ​

  1. Declare — write the portable fields of the exact service shape you need: bundle, handlers, vars, sensitive slots, typed bindings, retention.
  2. A host implements — the provider discovers the host at a versioned path and drives validate/prepare/apply, observe, and delete with UID, generation, and revision fences. Implementation, placement, capacity, credentials, and routing stay with the host.
  3. Bind — revisions hold typed capability bindings; attachments route the outside world in. Hosts publish what they support in Host Support Profiles.

Takoform is an Experimental specification project. The current design channel is the edge.forms.takoform.com/v1beta1 family, served over the forms.takoform.com/v1beta1 Host API with packages.forms.takoform.com/v1alpha4 package envelopes. The forms.takoform.com/v1alpha2 epoch and its packages.forms.takoform.com/v1alpha3 envelope are retained as the provider-v2 compatibility surface. Provider v2.0.0 is the current published client and provider v1.0.3 is the published Legacy client. Stable provider v2.1.1 is the release target for the Beta contracts; its descriptor remains candidate-only until the owner publishes it. The 15 Forms are Experimental and their packages remain unpublished. The 34 published Form Package identities from forms.takoform.com/v1alpha1 are immutable Legacy evidence. There is no current central approval or admission. Beta is an API/family channel, not a Stable or GA Form claim.

Current published: provider v2.0.0, retained v1alpha2 resources. Edge preview: provider 2.1.1-candidate-only, edge family unpublished, 12 publication blockers open.
